## 0. Видение (что строим)

Автономный конвейер, который **сам делает готовые к продакшну короткие видео**:

- **Источник:** последние новости парсятся из Threads (+ другие источники как плагины) ИЛИ
  тема задаётся вручную ИЛИ свои загруженные фото/видео.
- **Сборка с нуля:** сценарий (LLM по API) → озвучка (RU/EN) → моушн-графика (hyperframes)
  → говорящий ведущий (AI-аватар из стокового фото) → финальный mux с сабами.
- **Управление и доставка — через Telegram.** Домашний ПК (GTX 1070 Ti) — рендер-воркер.
  С телефона пишешь боту тему/команду — готовый mp4 прилетает в тот же чат.
- **Установка в один клик:** один `install.bat` ставит всё (окружения, веса, тулчейн,
  автозапуск воркера). Дальше комп работает сам, подключение — просто открыть чат с ботом.

Языки: **русский (Qwen3-TTS, локально) + английский (edge-tts, бесплатно)**.

## 2. Железо и облако: GTX 1070 Ti + Azure-кредиты ($25k+, Founders Hub)

**Решение 2026-06-10:** есть доступ к Azure-кредитам стартапа ($25k+, покрывают все
Azure-сервисы, вкл. Azure OpenAI). Стратегия — **cloud-first, локальное = fallback**:
качество выше, 1070 Ti разгружается до рендера hyperframes, а каждый облачный вызов
живёт за флагом с бюджет-капом (если кредиты кончатся — конвейер деградирует на
бесплатные локальные пути, не падает).

| Компонент | Primary (Azure, кредиты) | Fallback (бесплатно/локально) |
|---|---|---|
| Hyperframes (Chrome+ffmpeg) | — | ✅ Локально (как есть) |
| **TTS RU+EN** | **Azure Neural TTS** (`azure-v2` уже в `voice.py`!) | Qwen3 (RU) / edge-tts (EN) |
| **Говорящая голова** | **Azure TTS Avatar** (batch API, 1080p, VASA-1) | Wav2Lip локально |
| LLM-авторинг (сценарий+композиция) | **Azure OpenAI** (GPT-4o/4.1) | текущие провайдеры `llm.py` |
| AI B-roll (опц.) | **Sora 2** через `videogen/` (флаг, кап) | сток pexels/pixabay |
| Сабы (тайминг) | Azure STT batch (опц.) | whisper (как есть) |
| MisoTTS 8B / diffusion-аватары | ❌ не нужны | — |

### Azure-сервисы: цены и нюансы (проверено 2026-06)
- **TTS Avatar (batch):** ~биллинг посекундный (~$0.3–2/мин по регионам — сверить в
  своём регионе). **Standard-аватары** (каталог готовых ведущих) — без одобрения.
  **Custom photo avatar** (своё фото) — Limited Access: заявка, Microsoft-managed
  customers, ≥10 раб. дней, consent-видео. Для соло-проекта рассчитываем на standard;
  своё фото остаётся за Wav2Lip.
- **Neural TTS:** ~$16/1M символов. Ролик ~1k символов → копейки. RU-голоса:
  Dmitry/Svetlana(+HD); EN — большой каталог.
- **Sora 2:** $0.10/сек ($0.05 batch-тир). ⚠️ **API закрывается 24.09.2026** —
  используем пока живо, строго за флагом `videogen`.
- **Azure OpenAI:** сценарий+композиция ~центы за ролик; кэшировать промпты.
- Поставить **Azure budget alerts** на подписке (например, $200/мес) — кредиты чужие
  (стартап друга), жжём аккуратно и прозрачно.

### TTS по языкам (пересмотрено)
- **RU + EN:** Azure Neural TTS — основной (один провайдер на оба языка).
- Fallback RU: Qwen3-TTS (локально, уже есть). Fallback EN: edge-tts (уже встроен).
- В сценах с Azure-аватаром TTS входит в сам avatar-запрос (голос+видео одним вызовом).

## 3. Целевая архитектура

```
                         ┌─────────────── Telegram-бот (app/bot/) ───────────────┐
   твой телефон  ──────► │  /news  /make <тема>  upload фото/видео   progress     │
                         └───────────────┬──────────────────────────┬────────────┘
                                         │ ставит задачу в очередь    │ шлёт назад mp4
                                         ▼                            ▲
   news/ (Threads-парсер) ──► тема+факты ─► PIPELINE (task.py) ───────┘
   свои медиа (uploads) ─────────────────►   │
                                             ▼
        script (LLM/API) ─► scenes (тайминг по SRT)
              ┌──────────────────┼───────────────────────────┐
              ▼                   ▼                           ▼
       TTS (Qwen3 RU /      hyperframes/studio          avatar/ (НОВОЕ)
       edge-tts EN)         (моушн, плашки, B-roll)      стоковое фото → говорящее
              │                   │                       лицо (Wav2Lip)
              ▼                   ▼                           ▼
        audio.mp3        COMPOSITOR (video.py/assemble.py): слои на канвасе
                         ведущий + lower-third + заголовок + сабы по сценам
                                             │
                                             ▼  final mux → out.mp4 → Telegram
```

Три новых модуля + всё подключается через существующие fallback-цепочки (любой сбой →
деградация, не падение).

## 4. Удалённая работа + установка в один клик

**Ключевая идея:** Telegram-бот на **long-polling** не требует белого IP, проброса портов
или туннеля — работает за домашним NAT. Это и есть «подключение в один клик»:
бот крутится фоном на ПК, ты просто открываешь с ним чат с телефона.

- `app/bot/` — отдельный продуктовый бот (свой токен, НЕ токен Claude Code):
  - команды: `/news` (взять свежую новость из Threads), `/make <тема>`, приём фото/видео
    как контента, `/status`, выбор языка RU/EN, выбор аватара.
  - очередь задач (1 GPU → последовательно), индикатор прогресса (правит сообщение),
    по готовности шлёт mp4 новым сообщением (пуш на телефон).
- `install.bat` — **единая точка установки** (оборачивает существующие
  `setup-hyperframes.bat` + `setup-qwen.bat` и добавляет новое):
  1. основной `.venv` (uv), `.venv-qwen`, `.venv-wav2lip`;
  2. тулчейн hyperframes (Node, ffmpeg/ffprobe, headless Chrome);
  3. скачивание весов (Wav2Lip);
  4. генерация `config.toml` из шаблона, запрос токена бота и API-ключа LLM;
  5. регистрация автозапуска воркера (Windows Task Scheduler), чтобы бот всегда жил.
- Результат: скинул на комп `install.bat` → один запуск → дальше всё из Telegram.

## 5. Новые модули (дизайн)

### 5.1 `app/services/avatar/` — говорящая голова (Azure-first)
- `base.py` — ABC `TalkingHead.synthesize(script_or_audio, presenter, out_path, w, h) -> str`
  (`''` при ошибке = non-fatal fallback к чистой моушн-графике).
- `azure.py` — **основной провайдер**: Azure TTS Avatar batch synthesis API
  (submit → poll → download mp4). Принимает текст+голос (TTS внутри запроса) либо
  SSML; standard-аватар из каталога (`avatar_character`, `avatar_style`). 1080p/25fps,
  кодек H264; для оверлея «ведущий в углу» брать webm/vp9 с альфа-каналом, если регион
  отдаёт, иначе хромакей/кроп.
- `wav2lip.py` — **fallback-провайдер** (и единственный путь для своего фото):
  аудио + фото → лип-синк. Изолированный `.venv-wav2lip` + subprocess (как qwen).
  Веса `wav2lip_gan.pth` (~400 MB). Ставится опционально (если Azure-ключа нет).
- `__init__.py` — резолвер-цепочка `azure → wav2lip → ''` + флаги `avatar_enabled`,
  `avatar_provider`, `avatar_character` (Azure) / `avatar_portrait` (Wav2Lip).
- HeyGen/D-ID/Hedra не нужны — Azure закрывает облачный слот кредитами.

### 5.2 `app/services/news/` — источники новостей
- `base.py` — ABC `NewsSource.latest(topic=None, limit=N) -> list[NewsItem]`.
- `threads.py` — парсер Threads (неофиц., см. риски). NewsItem = заголовок+текст+медиа+ссылка.
- Плагины-альтернативы тем же интерфейсом: RSS, Telegram-каналы, X — чтобы не зависеть от Threads.
- LLM по API превращает NewsItem → короткий сценарий (хук в существующий `llm.py`).

### 5.3 `app/bot/` — Telegram-управление и доставка
- long-polling (aiogram/python-telegram-bot), очередь, прогресс, отправка mp4.
- приём своих фото/видео → кладёт в `local_materials_dir` (механизм уже есть).

### Существующее, что переиспользуем
- Загрузка своих медиа: `list_local_materials` + `local_materials_dir` уже работают.
- `studio`-движок (default) — добавим архетип `news` (ведущий + lower-third + заголовок + тикер).
- Композитор слоёв — расширение `video.py`/`assemble.py` (ведущий поверх hyperframes-фона).

## 7. Процесс выполнения: суб-агент на фазу + ревью Codex до 8/10

Под твоё требование «каждую фазу — отдельному суб-агенту Клода, потом Codex проверяет до 8/10»:

1. **Каждая фаза самодостаточна** (см. раздел 6): свой scope, файлы, критерии приёмки —
   суб-агент берёт фазу без знания остальных.
2. **Реализация:** суб-агент Клода делает фазу до состояния «Готово =», пишет тесты.
3. **Ревью-гейт:** Codex оценивает по рубрике (ниже) 1–10. **< 8 → правки → повтор**, пока **≥ 8**.
4. Только при ≥ 8 фаза мёржится, начинается следующая (с учётом зависимостей).

**Рубрика оценки (Codex), 0–10:**
- Критерии приёмки фазы выполнены полностью (вес ×3).
- Тесты есть и зелёные, покрывают happy-path + fallback (×2).
- Соблюдён стиль/идиомы проекта, non-fatal fallback не сломан (×2).
- Нет регрессий в существующем пайплайне (×2).
- Документация/конфиг обновлены (×1).

**Существующий код — под тем же гейтом.** Фаза 0 (аудит) прогоняет уже написанные модули
через ту же рубрику 0–10. Модуль с оценкой < 8 не «проходит как есть» — он попадает в реестр
`docs/CODE_AUDIT.md` с вердиктом (рефакторить/переписать/удалить) и чинится до того, как на нём
будут строить новые фазы. То есть оцениваем не только новую работу суб-агентов, но и наследие.

> На старте следующей сессии: создать для каждой фазы отдельную задачу/ветку, выдать суб-агенту
> текст фазы из раздела 6 + рубрику из раздела 7. **Начинаем с Фазы 0 — аудита.**

## 8. Риски и открытые вопросы

| Риск | Заметка / митигация |

| **Кредиты кончатся / отзовут** | Каждый Azure-вызов за флагом с fallback на бесплатный локальный путь (Qwen3/edge-tts/Wav2Lip/сток). Ферма не умирает — деградирует. |
